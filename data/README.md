# Data indexes

Generated by `node scripts/build-data.js` from `archive/ferias/sozai/*.js`. The archived Ferias site remains the source of truth; JSON files are committed so GitHub Pages needs no build step.

- `items.json`: keyed by original four-digit hexadecimal **item ID**, with English/Japanese name, rarity, price, stack, rank requirement, sort key, and original description. Rank requirement is not the same as the rank of an acquisition source.
- `item-sources.json`: keyed by item ID, then the original rank buckets `Kai` (low), `Zyoui` (high), `Sugo` (HR100/elite), `G` (G rank). Each bucket can contain `monsters` (monster ID and drop description), `quests` (quest ID, reward category, quantity and chance), and `gathering` (Warm/Cold/Breeding entries with location, map/point, day/night and chance). Gathering entries retain their original encoding for unusual cases.
- `monsters.json`: original monster IDs, names, readable URL slugs, available Ferias stat/carve HTML pages, and existing illustration/diagram paths per variant. Stat variants (`n`, `nh`, `ng`, `ni`, `nt`) and rank-specific carve columns (`h`) remain in `archive/ferias/mons/`; the monster UI loads only selected pages on demand.
- `quests.json`: original quest IDs, title, legacy file, and reward type labels. Includes quests from both the item reward index and the HTML tables (some event quests only appear in the latter). The new quest UI reads the selected legacy table on demand; detailed quests are not yet normalized JSON.
- `equipment.json`: original weapon and armor/deco names, type groups and compact per-item crafting requirements; **not yet** a complete structured stat database. Detailed weapon/armor pages remain in the archive.
- `weapon-pages.json`: generated lookup from a five-character weapon key (type prefix + original four-character hex ID) to the Ferias HTML table(s) containing that weapon. Repeated rows in the same table represent weapon levels. The new weapon UI reads only the selected legacy table on demand; this is not yet normalized stat data.
- `item-extras.json`: original compact item shop, combination, and other-use indexes; some entries refer to archived features. Retained for future decoding/filtering, not presented as complete normalized shop data yet.

Item URLs use the ID alone (`wiki/#/items/0188`). Rank/season/monster variants belong to sources, rather than being part of an item's identity. As new sections are built, extract detailed data into their own typed datasets before removing the legacy fallbacks.

Quest URLs use the original four-character quest ID (`wiki/#/quests/524B`). Weapon URLs use the original type prefix plus four-character weapon ID (`wiki/#/weapons/4009C` for a sword-and-shield), because different weapon types can reuse the same four-character code. Nine weapon names in the original name index have no matching HTML row and show a clear missing-detail notice.

Monster URLs use readable name slugs (`wiki/#/monsters/espinas`, `wiki/#/monsters/blangonga`); old Ferias-key URLs (`wiki/#/monsters/esp`, `wiki/#/monsters/dodobura`) still resolve and redirect to the readable version. `variant=ni` selects Zenith stats, and `rank=Zenith%E2%98%854` selects Zenith★4 drops. Only variants and drop ranks actually present in the archived monster pages appear in the UI.
