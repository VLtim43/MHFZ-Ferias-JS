# Data indexes

Generated by `node scripts/build-data.js` from `archive/ferias/sozai/*.js` and archived weapon tables in `archive/ferias/buki/*.htm`. The archived Ferias site remains the source of truth; JSON files are committed so GitHub Pages needs no build step.

- `items.json`: keyed by original four-digit hexadecimal **item ID**, with English/Japanese name, rarity, price, stack, rank requirement, sort key, and original description. Rank requirement is not the same as the rank of an acquisition source.
- `item-sources.json`: keyed by item ID, then the original rank buckets `Kai` (low), `Zyoui` (high), `Sugo` (Elite / HR5 in the item page), `G` (G rank). Each bucket can contain `monsters` (monster ID and drop description), `quests` (quest ID, reward category, quantity and chance), and `gathering` (Warm/Cold/Breeding entries with location, map/point, day/night and chance). Gathering entries retain their original encoding for unusual cases.
- `monsters.json`: original monster IDs, corrected names, readable URL slugs, available Ferias stat/carve source filenames, `statLabels` taken from real stat-page titles, `dropRanks` extracted from the carve table headers, `redirects` for unusable/redirect-only stat files, local Fandom renders/icons in `art`, verified Fandom entry titles in `wikiPages`, and Ferias part diagrams in `images`. Source names and image/page mappings live in `scripts/monster-art.json`; refresh them with `node scripts/import-monster-art.js`, then rebuild. Filename suffixes do **not** identify the displayed variant: `nh` may be Henshu, Goushu, Kishu, Supremacy, or Normal. Stat variants and carve ranks are independent classifications: Akantor has Normal/Henshu/GR stat files but HR/Elite/GR drop columns. The monster UI loads local detail JSON on demand.
  The same manifest lists excluded non-browseable entries and base-icon fallbacks for variants. Excluded IDs keep their names for historical item-source labels, but have no monster page or packaged monster-detail JSON.
- `quests.json`: original quest IDs, title, source file, `sourceAvailable` (file exists), `sourceAnchorAvailable` (entry exists), `detailAvailable` (matching standard detail table exists), and reward type labels. Includes quests from both the item reward index and the HTML tables. Standard quests and event/lottery listings are packaged as HTML fragments in local JSON, not yet normalized into typed fields. Missing entries link to the upstream source file without an invalid fragment.
- `equipment.json`: original weapon and armor/deco names, type groups and compact per-item crafting requirements; not a complete structured armor/deco stat database.
- `weapon-pages.json`: generated lookup from a five-character weapon key (type prefix + original four-character hex ID) to the Ferias HTML table(s) containing that weapon.
- `weapons-index.json`: compact player-weapon search index with name, type, source-tree categories, type-group tags, and detail/Tower availability. Category labels are normalized only for obvious spelling variants; weapons absent from source-tree links retain an explicit `Uncategorized` label (or a known group-derived category). Nine named RNG Cat weapons have no indexed detail row.
- `weapon-details/index.json` and `weapon-details/<prefix>.json`: on-demand shards keyed by the first three characters of the **five-character** weapon ID. Each record holds separate source tables with their original column labels and rows, including Lv100 evolution rows, numbered RNG Cat variants, and separate Tower enhancement tables. Cell text preserves ambiguous source values; `parts` retains item/weapon links and item quantities where explicit, `sharpness` holds ordered bars, and each row's `anchor` links back to the original HTML. Companion weapons are not included in these shards.
- `weapon-trees.json`: weapon branches extracted from source tree listings, with depth, names, direct-craft markers, and wiki links.
- `gear-index.json`, `gear-details/<prefix>.json`, `gear-trees.json`, and `gear-unavailable.json`: searchable armor, Palico armor, decorations, cuffs, and sigils; on-demand source table rows with per-level stats and materials; armor-set upgrade branches linking individual pieces. `gear-unavailable` lists indexed names without a source detail row so item-use links do not lead to missing pages. Built from `archive/ferias/bougu/`, with no runtime archive requests.
- `quest-details/<file>.json` and `monster-details/<id>.json`: on-demand source table fragments packaged into JSON at build time. The browser parses these fragments for the existing safe table renderer; it does not fetch archived HTML. Monster illustrations and diagrams referenced by `monsters.json` are copied into `assets/` during generation.
- `item-extras.json`: original compact item shop, combination, and other-use indexes; some entries refer to archived features. Retained for future decoding/filtering, not presented as complete normalized shop data yet.
- `item-shops.json`: decoded shop names and original price/condition text, keyed by item ID. This is item acquisition data, not a complete shop catalog.
- `item-uses/index.json` and `item-uses/<prefix>.json`: item-to-equipment crafting uses, usually sharded by the first three characters of item ID (dense `330` items use the full ID). Each record has an equipment ID, name, original quantity string, and where applicable craft type or level. `weapons`, `armor` and `decorations` are separate arrays. Signed quantities, placeholder equipment IDs, and missing names are retained without inventing replacements. Look for the full item ID in `index.json` first, then its three-character prefix.
- `skills.json`: local Skill Descriptions and Zenith Skill Descriptions, preserving source sections, category notes and buffs, activated effect names, point thresholds, and descriptions. The wiki renders both complete tables; gear skill points link to their group, and named Zenith effects link to their exact row. Unmatched source labels remain plain text rather than linking to an unrelated skill.

Item URLs use the ID alone (`wiki/#/items/0188`). Rank/season/monster variants belong to sources, rather than being part of an item's identity. As new sections are built, extract detailed data into their own typed datasets before removing the legacy fallbacks.

Quest URLs use the original four-character quest ID (`wiki/#/quests/524B`). Weapon URLs use the original type prefix plus four-character weapon ID (`wiki/#/weapons/4009C` for a sword-and-shield), because different weapon types can reuse the same four-character code. Nine weapon names in the original name index have no matching HTML row and show a clear missing-detail notice.

Armor and decoration URLs use the original slot/type prefix plus four-character ID (`wiki/#/armor/h0001`, `wiki/#/decorations/d031F`). Armor set trees link each piece to its own detail page; source rows without indexed names are not included.

`wiki/#/weapons` shows one card for each player-weapon type. A type card links to its browsable list (`wiki/#/weapons?type=4` for sword-and-shield weapons); search and category parameters can be combined with `type`.

Monster URLs use readable name slugs (`wiki/#/monsters/espinas`, `wiki/#/monsters/blangonga`); old Ferias-key URLs (`wiki/#/monsters/esp`, `wiki/#/monsters/dodobura`) and previous name slugs still resolve and redirect to the readable version. `variant=ni` selects Zenith stats, and `rank=Zenith%E2%98%854` selects Zenith★4 drops. Only variants and drop ranks actually present in the archived monster pages appear in the UI.

Run `node scripts/check-data.js` after regenerating. It checks references, equipment-use extraction counts, weapon index/detail/row/Tower coverage and original anchors, and reports quests whose archived detail page is unavailable.
